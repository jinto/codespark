### 반복의 구조적 원인

**(1) `workspacePath`가 타입이 아니라 관습이다.**
`String`으로 58군데를 돌아다니는데 승인된 URI↔raw 변환 함수를 거치는 건 9군데뿐.
CLAUDE.md가 *"두 네임스페이스를 섞지 말 것"*이라고 적어뒀지만 그걸 강제하는 건 문장뿐이다.
경로 비교 구현이 4가지(`sameWorkspace`, `belongs(to:)`, `cwdBelongsTo`, 맨 `==`),
틸드 전개가 3벌, `shellQuoted`가 3벌.

**(2) 선택이 두 개의 키로 표현된다.**
`selectedProjectID`(즉시 이동)와 `selectedProject`(git 왕복 뒤 도착)가 한 왕복 동안 불일치한다.
이 창이 오늘 하루에만 두 번 버그로 나타났고(사이드바 껌뻑임 — 수정됨,
그리고 아래 C5의 데이터 오염 — 미수정), 세 곳이 더 남아 있다.

**(3) 고쳐진 버그가 형제에게 가지 않는다.**
`RemoteDirectoryLister`에서 고친 두 가지(파이프 동시 배수, `terminationHandler`를 `run()` 전에 설치)가
`GitWorktreeService`·`GitBranchService`에는 그대로 남아 있다. 7개의 `Process` 사용처에 4가지 대기 전략.

**(4) 게이트가 열려 있다.** 아래 H3·H4·H5. 리포의 문화 전체가 "테스트로 막는다"인데,
막는다고 선언한 것 중 셋이 실제로는 아무것도 막지 않는다.

## 2. Critical (5)

### C1 — ssh/scp 인자 인젝션 → 로컬 임의 명령 실행
`SSHConnectionInfo.swift:30,34` (호스트 검증이 `!isEmpty`뿐), 호출부
`GitWorktreeService.swift:143-152`, `RemoteDirectoryLister.swift:114`,
`ClipboardImageHandler.swift:38`, `SSHConnectionInfo.swift:85,111`.

호스트가 검증 없이 argv에 들어가고 `--` 구분자가 없다
(`hasPrefix("-")`·`validateHost`·`"--"` 검색 결과 **전체 0건**).
ssh는 대시로 시작하는 인자를 옵션으로 읽으므로 `-oProxyCommand=…`가 로컬에서 실행된다.
codex가 이 기계에서 실증했다.

값은 New SSH Project 시트의 자유 입력 → 스토어 저장 → **10초 폴링이 반복 실행**.
리포는 호스트를 셸 따옴표로 감싸고 이유까지 주석으로 적어뒀다 —
따옴표는 셸을 막지 argv 위치를 막지 못한다. 방어가 한 층 밀려 있다.

**수정**: `SSHConnectionInfo.init?(uri:)`에서 대시 선행 호스트 거부 + 목적지 앞에 `--` 삽입.

### C2 — 마이그레이션 중단이 스토어를 영구히 벽돌로 만든다 (재현됨)
`store.zig:547-573`, `setSchemaVersion:578-584`, `migrateV2:640-645`,
`ProjectCoreClient.swift:64`.

`migrate()`가 `migrateVN`과 `setSchemaVersion(N)`을 **트랜잭션 없이 별개 문으로** 실행하고,
`setSchemaVersion` 자체가 `delete` + `insert` 두 문이다. `migrateV2`는 `alter table add column` —
멱등이 아니다(재실행 시 `duplicate column name`).

재현:
```
1) 새로 생성            → OPEN OK, schema_version = 3
2) 버전을 1로 되돌림     → OPEN FAILED: error.Database
3) 버전 행을 삭제        → OPEN FAILED: error.Database
```
3번은 `setSchemaVersion`의 delete와 insert 사이에서 죽었을 때 남는 상태다.

이후 스토어는 **다시 열리지 않고**, `ProjectCoreClient.live`가 `fatalError` —
**매 실행마다 앱이 죽는다.** 제시되는 복구책은 DB 삭제, 즉 모든 프로젝트와 세션.

**수정**: `migrate()` 전체를 `begin immediate`/`commit`으로 감싸고(SQLite DDL은 트랜잭션 가능),
`setSchemaVersion`을 단일 `insert or replace`로.

### C3 — 실패하는 `Store.open`마다 sqlite 핸들 이중 close (재현됨)
`store.zig:22`와 `:25`.

```zig
errdefer _ = sqlite.sqlite3_close(db);   // ①
var store = Store{ .db = db.? };
errdefer store.deinit();                 // ② → sqlite3_close(self.db)
```
errdefer는 역순으로 풀린다 → ②가 닫고 ①이 같은 핸들을 다시 닫는다.
guard malloc 아래서 세그폴트 확인. 출하 바이너리는 ReleaseFast이므로 **UB**.
C2가 이 경로를 현실로 만든다.

**수정**: `:22`의 errdefer 삭제. `:25`가 이미 덮는다.

### C4 — 복원 도중 죽으면 아직 안 돌아온 탭이 영구 삭제된다
`store.zig:353` (`retireStaleInterruptedSessions`), `:407`에서 제일 먼저 호출.

이 함수는 `interrupted` 상태의 **모든** 행을 무조건 닫는다. 의도(옛 탭이 무한 누적되는 것 방지)는 주석에 있다.
그런데 복원은 설계상 느리다 — 탭마다 왕복 하나 + ssh 접속, 행은 `consumeInterruptedSession`으로 하나씩 빠진다.
복원 중간에 강제 종료되면 다음 실행이 **나머지를 읽기 전에 폐기한다.** 조용히 사라진다.

테스트 없음: `store_test.zig:933,977,1016,1084`은 전부 복원을 끝까지 돌린다.

**수정**: "지금 interrupted인 전부"가 아니라 **나이 또는 실행 ID 기준**으로 폐기.

### C5 — `newSession`이 프로젝트 B에 워크스페이스 A를 붙여 영구 기록한다
`AppModel.swift:668-669`, `:681`, `startAndAttachSession:623-631`, 가드는 `:656`.

```swift
guard let projectID = selectedProjectID else { return }   // B
guard let project   = selectedProject   else { return }   // A  ← 인접한 두 guard, 서로 다른 키
```
`workspacePath`는 A의 것에서, 세션은 B 소속으로 만들어진다. 그리고 **스토어 쓰기가 가드보다 먼저다** —
`:656`의 `guard selectedProjectID == projectID`는 메모리상 `liveSessions` 추가만 막는다.

결과: `project_id = B`, `workspace_path = A의 디렉터리`인 행. 다음 실행의 복원이 그걸 B의 탭으로 열고,
어느 워크트리에도 안 맞으니 `groupSessions` 폴백이 B의 main에 붙인다 —
**B 탭바에, A 디렉터리에서 열린 탭. 재시작을 넘긴다.**

창의 폭은 `core.projectDetail` 왕복 이상, 원격이면 워크트리 refresh까지 최대 20초.
사이드바 클릭 → Cmd+T면 재현.

`newAgentSession:861-865`가 같은 짝. `syncProjectSessionDetails:1404-1411`은 `selectedProjectID`(B)로
`projects`를 찾아 `liveSessions`(A)를 써넣는데, `terminalHostDidClose:1459`가 부르므로
**아무 셸이나 끝나면** A의 세션 목록이 B의 요약 행에 찍힌다 —
그리고 그 필드가 오늘 고친 `workspaces(for:)`가 읽는 바로 그 필드다.

**더 나쁜 변종**: `newAgentSession:863`은 A의 **transport**를 읽는다.
로컬 A에서 ssh B로 옮긴 직후면 **로컬 셸을 열어놓고 ssh 프로젝트 소속으로 기록한다.**

**수정 — 3단계, 앞의 둘은 공짜다** (codex 판단):
1. **가드를 추가하지 말 것.** `guard project.id == projectID`를 넣으면 오염이 *조용히 삼켜진 Cmd+T*로 바뀔 뿐이다.
   "가끔 Cmd+T가 안 먹어요"로 보고되는 종류다. 그리고 이 관습은 이미 존재하고 이미 실패했다 —
   `:749-750`, `:840`, `:1077`, `:435` 네 곳이 올바르게 가드하고 `workspaces(for:)`에는 10줄짜리 설명 주석까지 있는데,
   **세 곳을 놓쳤다.** 문서화된 관습이 43% 미적용이면 사람이 부주의한 게 아니라 **기전이 틀린 것**이다.
2. **세 곳 모두 `projects.first { $0.id == projectID }`(= `ProjectSummaryViewData`)를 읽게 한다.**
   요약은 id로 키가 잡히므로 **자기 자신과 불일치할 수 없다.**
   세 곳이 `selectedProject`에서 꺼내 쓰는 것은 `path`와 `transport`뿐이고 둘 다 요약에 있다.
   타입 변경 0, 테스트 변경 0. 위의 "더 나쁜 변종"이 여기서 죽는다.
3. **그래도 `newSession`은 안 닫힌다.** `:674-675`의 `workspacePath` 유도가
   `activeWorkspacePath`와 `workspaces`를 읽는데 둘 다 아직 A의 것이고,
   `workspaces.contains(where:)`가 **A의 그룹핑을 검사하므로 통과한다.**
   → §5-2의 `Selection` 타입이 진짜 수정이다.

## 3. High (8)

**H1 — `terminationHandler`를 `run()` 뒤에 설치, 그리고 그 하나가 전부를 얼린다.**
`GitWorktreeService.swift:580-582`, `GitBranchService.swift:73-78`.
`readDataToEndOfFile()`가 반환한 시점 = 프로세스 종료 시점이고, 그 뒤에 핸들러를 단다.
Foundation은 종료 후 설치된 핸들러를 부를 의무가 없다(리포 자신의 주석 `GitWorktreeService:530-535`가 인정).
증폭기: `refreshWorktrees:76-84`가 모든 refresh를 이전 것 뒤에 줄 세운다(`await previous?.value`).
한 번 매달리면 **이후 전부가 영원히 대기**하고 10초 폴링이 계속 Task를 쌓는다.
`GitBranchService`는 타임아웃조차 없고 `isRefreshing`이 `true`로 굳어 브랜치 라벨이 세션 내내 얼어붙는다.

→ `RemoteDirectoryLister.exitStatus(of:):247-257`이 이미 올바른 템플릿이다.

*CLAUDE.md 결정 하나에 대한 반박(codex)*: "refresh는 겹치면 버리지 않고 줄을 선다"는 이유는 타당하나,
**완료가 보장되지 않는 작업 뒤에 줄을 세우면 일시적 실패가 영구적 실패로 승격된다.**

## 3-bis. 오늘(2026-08-30) 작업의 사각지대 — 셋

세 건 모두 어제·오늘 손댄 기능 안에 있고, 전부 **조용히 실패한다**.

**B1 — 원격 OSC 7이 percent-encoding을 하지 않는다.**
`SSHConnectionInfo.swift:281,289,294`가 `$PWD`를 날것으로 찍는다.
Ghostty는 `uri.path.toRawMaybeAlloc(...)`로 **percent-decode** 한다
(`vendor/ghostty/src/termio/stream_handler.zig:1189`).
공백이 든 원격 디렉터리는 `std.Uri` 파싱에 실패해 **보고가 사라지고**(탭의 cwd가 그 자리에 얼어붙는다),
이름에 `%20`이 들어 있으면 공백으로 디코드돼 **엉뚱한 경로가 기록된다**.
다음 복원이 낡은 디렉터리로 간다. Ghostty 자신의 shell integration은 인코딩한다 — 우리 재구현만 안 한다.
→ 세 스니펫 모두에서 `$PWD`의 공백·`%`·`#`·`?`를 이스케이프.

**B2 — 첫 stanza가 prunable이면 main 워크트리 표시가 사라진다.**
`GitWorktreeService.swift:305-308`이 `if path != nil { isFirst = false }` 후 continue하므로
**어떤 워크트리도 `isMainWorktree`를 받지 못한다.**
그러면 `projectIdentityLine:173`의 `.first(where: \.isMainWorktree)?.branch`가 nil →
**`ee72b49`에서 만든 `main on emac`이 조용히 호스트만 표시로 되돌아간다.**
`groupSessions:235`도 `worktrees[0]`로 폴백한다.
→ main을 **서수가 아니라 리포 경로 일치**로 판정.

**B3 — `numberedPlaces`가 사이드바를 O(P²)로 만들었다.**
`2770f3d` 이전의 `numberedProjects`는 `orderedProjects.prefix(9).map(\.id)`로 사실상 공짜였다.
지금은 프로젝트마다 `sidebarWorktrees(for:)` → `groupSessions`를 돌고,
`numberedIndex(forProject:)`가 **행마다 전체를 재계산**한다.
게다가 `CodeSparkApp.swift:143`의 `.commands` 바디가 **Cmd 게이트 없이** 매 `@Published` 변경마다 평가한다 —
`liveSessions[i].lastCwd`가 프롬프트마다 바뀌므로 **`ls` 한 번에 사이드바 그룹핑이 여러 번 재계산된다.**

## 4. Medium / Low

### 성능

enum WorkspaceAddress: Hashable {

### 5-2. 선택은 하나의 값

지금: `selectedProjectID`(즉시) + `selectedProject`(왕복 뒤). 둘이 불일치하는 창이 상시 존재한다.

```swift
enum Selection {
    case none
    case pending(id: String, showing: ProjectDetailViewData?)  // 눌렀고, detail은 오는 중
    case loaded(ProjectDetailViewData)

    var id: String? { … }
    var detail: ProjectDetailViewData? {        // *이* 프로젝트의 것일 때만
        if case .loaded(let d) = self { return d }; return nil
    }
    var displayDetail: ProjectDetailViewData? { … }   // 기다리는 동안 사이드바가 빌려 쓰는 것
}
```
`.pending` 팔이 핵심이다 — "B를 눌렀고 B의 detail은 오는 중"은 **실제로 표현해야 하는 상태**다.
다만 `(id: B, detail: A)`는 **구성할 수 없다.** 둘 다 필요한 쓰기는 `.loaded`를 매칭해야 하고,
그게 손으로 썼어야 할 가드인데 이번엔 **컴파일러가 강제한다.**
`apply(detail:)`과 `clearDetailState()`가 유일한 전이가 되므로,
`activeWorkspacePath = nil`의 순서 규칙(CLAUDE.md가 문단 하나를 쓴 그것)도 한 곳에 모인다.

그러면 C5도, H7도, 오늘 고친 껌뻑임도 애초에 쓸 수 없다.
`workspaces(for:)`가 "어느 키로 판정하나"를 고민할 일 자체가 없어진다.
마이그레이션 비용은 크지 않다 — 두 프로퍼티를 읽는 곳이 이미 전부 조사돼 있다(§2 C5, §3 H7).

### 5-3. 표현은 순수 함수

### 5-4. 서브프로세스는 하나의 헬퍼

## 7. 검토자들이 "고치지 말라"고 한 것

전수조사에서 나온 결론 중 **현상 유지가 옳다**고 판정된 것들. 다음 사람이 다시 파헤치지 않도록 적어둔다.

- **Ghostty 임베딩 계층**(`GhosttyRuntime`/`GhosttyTerminalSurfaceView`/`GhosttyTerminalHost`)은 그대로 둔다.
  물리 픽셀 `convertToBacking`, 제어문자를 원문자+Ctrl로, `wantsLayer` 금지,
  `close_surface_cb`의 userdata가 뷰의 것이라는 사실, OSC 7의 localhost 요구 —
  대체 불가능한 지식이 여기 있고 재작성은 전부 다시 배우게 된다.
- **원격 워크트리를 로컬 경로와 같은 문자열 공간에 넣은 결정**도 옳다.
  틀린 것은 결정이 아니라 **타입**이다(§5-1).
- **`TerminalHostProtocol` + `NoOpTerminalHost`**는 단일 구현 추상화처럼 보이지만
  모델 계층 전체를 Ghostty 없이 유닛 테스트할 수 있게 하는 것이라 값을 한다.
- **`project_free_*`의 소유권 경계는 잘 지어졌다.** 모든 free가 구조체를 zeroing하므로
  Swift에서 이중 free를 해도 no-op이고, `project_free_string`의 sentinel 처리도 `dupeZ`와 정확히 맞는다.
  중첩 `errdefer` 사슬(`c_api.zig:233-244`, `:267-291`)은 배열 포인터를 루프 **이후에** 공표하므로 이중 free가 없다.
- **SQL 인젝션 없음.** 모든 문이 컴파일 타임 리터럴 + `?N` 바인딩.
- **탭 중복 복원 경로는 만들 수 없었다.** `retireStaleInterruptedSessions`가 reconcile 안에서 **먼저** 돌고,
  `consumeInterruptedSession`이 대체 세션이 생기는 즉시 행을 폐기하며, 두 업데이트 모두 상태 가드가 걸려 있다.
  (C4의 *손실* 경로는 별개다.)
- **탭 순서 보장은 정확하다.** `sessionsForProject:664-669`의 `order by created_at asc, rowid asc`가
  인메모리 append 순서와 맞는다 — CLAUDE.md 설명 그대로.
- **주석 밀도는 줄일 것이 아니다.** 발견된 문서-코드 괴리(§4의 `sameWorkspace`,
  `belongs(to:)`가 `groupSessions`의 규칙을 다시 구현하는 것)는
  **산문을 줄이라는 근거가 아니라 그 불변식을 검사하는 테스트를 쓰라는 근거**다.
