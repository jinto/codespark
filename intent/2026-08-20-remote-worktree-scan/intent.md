# Intent: 원격(ssh) 프로젝트 워크트리 스캔

- Date: 2026-08-20
- Status: retroactive — spec.md/plan.md에서 2026-10-20 재구성
- Next: spec.md

## Problem
로컬 프로젝트는 사이드바에 워크트리가 자식 행으로 펼쳐지고, 탭바·`Cmd+[/]`·`Cmd+1…9`가 워크트리 단위로 스코프된다. 원격(ssh) 프로젝트는 이 전부에서 배제되어 있어, 원격 리포에 워크트리가 여러 개 있어도 앱은 프로젝트 하나로만 본다.

## Proposed outcome
- 원격 프로젝트도 로컬과 완전 동등하게: 워크트리 스캔, 사이드바 행, 그 워크트리에서 탭 열기, 원격 워크트리 생성/삭제.
- 원격은 일상적으로 끊기므로, 조회에 실패해도 직전 워크트리 목록이 화면에 남아 메인 영역이 비지 않는다 ("조회 실패는 워크트리 삭제가 아니다").
- 워크트리 삭제가 실패하면 탭이 살아남는다 (git 삭제 성공 후에만 탭을 닫음 — 로컬 동작도 같이 바뀜).
- 워크트리 생성/삭제 직후의 갱신 요청이 조용히 버려지지 않는다.
- 새 화면 없음 — 기존 사이드바·탭바·단축키가 그대로 따라온다.

## Affected users and systems
- 원격(ssh) 프로젝트를 쓰는 CodeSpark macOS 앱 사용자
- 워크스페이스 소속 키(그룹핑·선택·복원·삭제)를 공유하는 탭/사이드바 동작, 로컬 워크트리 삭제 순서

## Constraints
- 원격 워크트리 주소는 `ssh://` URI이고 스토어 스키마는 바꾸지 않는다. 같은 원격 위치가 두 개의 키가 되면 탭이 미아가 되므로 URI 형태는 하나로 고정한다.
- 워크스페이스 주소(URI)와 원격 raw 경로(git 인자, 작업 디렉터리)를 절대 섞지 않는다.
- 백그라운드 스캔이 비밀번호 프롬프트에 매달리면 안 된다 (키 인증 전용); 연결된 뒤 멈추는 경우에도 하드 타임아웃.
- 프로젝트 수만큼 ssh를 한꺼번에 띄우지 않는다. 연결 재사용(ControlMaster)은 새 실패 모드 때문에 쓰지 않는다.
- sshd 없이 CI에서 검증 가능해야 하고, 기존 테스트 192개는 그린 유지.

## Out of scope
- `remotePath`가 없는 `ssh://host` 프로젝트 — 리포 위치를 모르므로 스캔하지 않는다.
- IPv6 리터럴 호스트 (기존 파서 한계, 이번 작업이 만든 결함이 아님).

## Open questions
- 알려진 대가: 키 인증이 안 되는 호스트에서는 워크트리 행이 에러 배너 없이 조용히 안 나온다. 사용자가 직접 누른 생성/삭제 실패만 기존대로 표시된다. 이 수준으로 충분한지는 스펙에서 수용한 상태.
